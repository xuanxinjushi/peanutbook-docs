# Audiobooks (text-to-speech)

The writer can read a book's chapters aloud and turn them into an audiobook: one
MP3 per chapter, ready to listen to in the browser or upload (ACX/Audible-ready
loudness is the default).

- **Per book**: open a book and click **🎧 Audio** in its toolbar
  (`/books/<book>/audio/`).
- **Control panel**: **🎧 Audio** in the top bar (`/audio/`) for the TTS worker,
  engines, voices and every job across all books.

## How it works

Speech is generated by a separate **TTS worker** process that runs next to the
speech model (usually on the machine with the GPU). The writer sends it the
chapter text; the worker synthesizes it sentence by sentence and writes the
audio into the book folder:

```
<book>/audio/tracks/<chapter>/
  script.jsonl        the chapter split into segments (text + pause)
  segs/<key>.wav      one file per segment
  <chapter>.mp3       the finished chapter (192 kbps with ACX on, 64 kbps otherwise)
  track.json          voice/settings used and where each segment starts
```

The assembled WAV is deleted once the MP3 is written; a retake rebuilds the
chapter from the segment files in seconds. Disk use per hour of audio: about
170 MB of segments plus 86 MB (ACX) or 29 MB (64 kbps) of MP3.

Because the worker owns the queue, generation keeps running when you close the
browser, and a restarted worker still lists its jobs. Jobs interrupted by a
restart can be retried; finished segments are kept, so a retry resumes.

Each segment file is named after a hash of its text, voice and settings. Editing
a chapter therefore only re-synthesizes the sentences that changed, and switching
voice never deletes the old audio (it becomes "old takes" you can clean up).

## Start the worker

Engines currently supported:

| Engine | Kind | Needs |
|---|---|---|
| CosyVoice | local, GPU | a [CosyVoice](https://github.com/FunAudioLLM/CosyVoice) checkout and its conda env |
| OpenAI-compatible `/v1/audio/speech` | cloud (or any compatible server) | an API key |

With CosyVoice installed in a conda env named `cosyvoice`:

```bash
conda activate cosyvoice
python <peanutbook>/web/audiobook/tts_worker --cosyvoice-root ~/CosyVoice
```

or in the background (restart/stop with the same script):

```bash
COSYVOICE_ROOT=~/CosyVoice web/audiobook/run_tts_worker.sh        # start / restart
web/audiobook/run_tts_worker.sh stop
```

The worker listens on port 1980. When Docker is installed it binds to the
Docker bridge address, so the writer container can reach it but other machines
can't; the writer finds it automatically. Use `--host`, `--port` and `--token`
to change that, and set the matching URL and token on the control panel.

The CosyVoice location, model folders, ffmpeg path, the folders the worker may
write to, and how long an idle model stays on the GPU can all be changed on the
control panel; they are saved by the worker. The control panel also shows the
command (and a systemd user service) for your setup.

!!! note "Docker"
    The writer container usually sees books at different paths than the host.
    Docker bind mounts are translated automatically; for anything else, add a
    `writer path => worker path` line under **Path mapping** on the control panel.

## Generate a book

1. Pick the **edition** (language). The chapter list follows the book's layout:
   the preface, `chapterN-*/chapterN<_lang>.md` in order, then `chapterx`.
   **＋ Add file** adds any other Markdown file, optionally only the part between
   two headings.
2. Pick a **voice**, a **style** and, for styled voices, a **delivery
   instruction** (blank = calm narration). **▶ Preview voice** reads a sample with
   exactly these settings.
3. Click **⚡ Generate** on a chapter, or **Generate everything missing**.

Each running chapter shows segments done, ETA, and the real-time factor. When a
chapter finishes it is assembled and exported; **▶** plays it in the bottom
player, which continues with the next chapter.

### What is read aloud

Headings (optional), paragraphs, verse lines and blockquotes. Images, code,
tables, math, raw LaTeX, HTML comments, footnote bodies and peanutbook layout
markers are skipped. `Chapter 3: Title` is read as "第三章，Title" in Chinese
editions. Long paragraphs are split at sentence ends.

Fix pronunciations with `<book>/audio/glossary.tsv` (one `written<TAB>spoken` per
line).

## Proofread and retake

**☰ Segments** opens the chapter as text. While the chapter plays, the current
line is highlighted; click any line to jump there. **↻** on a line (or select
several and **Retake selected**) makes a fresh take, and the chapter is
reassembled automatically. Each take sounds a little different, so retake until a
line sounds right.

## Voices

On the control panel:

- **Built-in** speakers (CosyVoice SFT model: 中文男, 中文女, 英文男, ...).
- **Cloned** voices: upload 5–30 s of clean speech (or record it in the browser)
  together with an exact transcript, and give it a name. It appears in every
  book's voice list. Cloned voices can be deleted again; the first change backs
  up the model's original `spk2info.pt` as `spk2info.pt.orig`.

Styles for cloned CosyVoice voices:

| Style | Effect |
|---|---|
| Styled | follows the delivery instruction |
| Styled, no reference bleed | instruction plus text, without the reference clip's words in the prompt |
| Plain clone | continues the reference recording's delivery |

## Clean up

**🧹 Clean up** (whole book) or a chapter's **⋯** menu:

- *Delete old takes*: segments the current text/voice no longer use.
- *Delete segment files*: keep only finished chapters (retakes then need a full regeneration).
- *Delete chapter WAVs*: keep the MP3s (only needed for chapters made before WAVs were removed automatically).
- *Delete all audio*.

**⬇ All MP3s (zip)** downloads the finished chapters, numbered in reading order.

## Control from the server

- **Control panel** (`/audio/`): worker status and GPU memory, engine settings,
  **Unload models** to free the GPU, all jobs with logs, cancel/retry, clear history.
- **Django admin** (`/admin/`): *TTS settings* and per-book *audio settings*.
- **Worker HTTP API** (`/api/status`, `/api/jobs`, ... on port 1980): see
  `web/audiobook/tts_worker/server.py`.

## Adding another engine

Subclass `Engine` in `web/audiobook/tts_worker/engines/` (implement
`synthesize(text, voice, options) -> (pcm16_bytes, sample_rate)` and, optionally,
`voices()`, `add_voice()`, `delete_voice()`, `unload()`), then register it in
`engines/__init__.py`. Its settings (`config_fields`) show up on the control
panel automatically.
