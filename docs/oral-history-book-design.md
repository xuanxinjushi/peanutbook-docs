# 口述历史书：规划与实现方案

> 状态：设计稿（2026-10-11），已按第 7 节的决定更新。内部文档，不发布到 peanutbook-docs。
> 相关：[audiobook 功能](../web/audiobook/)（TTS worker、Whisper 转写、声音克隆）、[AI 写作助手](ai-book-writing.md)。

## 1. 要做成什么

**用户讲自己的故事**：用户对着电脑或手机说，系统把口述变成一本**可信、保留本人口吻**的书（自传、回忆录、家族史），并顺带产出有声书。语言为普通话或英文（也包括两者夹杂）。

```
采访录音  ──►  逐字稿（带时间戳、说话人）  ──►  素材库（主题 / 时间线 / 人物 / 金句）
          ──►  目录规划  ──►  章节初稿（AI 辅助，每段可追溯到原录音）
          ──►  人工编辑定稿  ──►  peanutbook 构建：PDF / EPUB / 网站
          ──►  有声书：原声片段 + 讲述者克隆声音朗读
```

与普通写书最大的不同在于两点：

1. **原材料是声音，不是文字**。转写的准确度决定了一切，而且必须能随时回听核对。
2. **真实性是生命线**。AI 只能整理和润色，不能编造。每一段成稿都要能指回"他在哪次采访的哪一分钟说过这句话"。

## 2. 角色

讲述者就是用户本人，同时也是编辑。没有专职采访者，**由 AI 担任采访者**：提问、追问、提醒还缺什么。

| 角色 | 谁 | 做什么 |
|---|---|---|
| 讲述者 + 编辑 | 用户 | 口述，校对逐字稿，选目录方案和成稿风格，定稿 |
| 采访者 | AI | 按人生阶段提问，根据已讲内容追问，找出素材缺口 |
| 家人 / 审阅者（可选） | 用户邀请 | 读初稿，补充、纠错、确认涉及他人的内容能否公开 |

偶尔也会有"两人对谈"的场景，比如用户采访父母。说话人分离要支持，但不是主路径。

## 3. 完整流程

### 3.1 准备与"AI 采访"模式

用户不需要事先准备什么，打开"讲述"页面就能开始。

- **AI 采访模式**（主路径）：
  1. 屏幕上显示一个问题，比如"你最早的记忆是什么？"。可以选择用 TTS 把问题读出来，用的是用户选定的声音（现有功能）。
  2. 用户点"开始讲"，讲完点"停"。这一段录音立即在后台转写。
  3. AI 读到转写结果后，给出 1 到 2 个**追问**（"你说的'那条河'在哪里？那时你几岁？"），或者建议转到下一个话题。
  4. 每一问一答保存为一个 `turn`，挂在当天的 session 下面。
- **自由讲述模式**：不要问题，想到什么讲什么，一次讲多长都可以。也可以导入手机上的录音。
- **提纲**：内置一套人生阶段提纲，包括童年、求学、工作、家庭、时代大事、感悟，每个阶段 5 到 10 个问题，用户可以增删。AI 会根据已经讲过的内容跳过重复的问题，并优先问素材缺口（3.5 节）。
- **录音质量**：每次开始前先自动录 5 秒测试，用现有的 `clipcheck` 检查。太吵或太小声就提示。
- **节奏**：建议每次 20 到 60 分钟。一本 10 到 15 万字的书，大约需要 10 到 20 小时的口述。
- **授权**：本人讲述本人的故事，不需要知情同意书。但**克隆自己的声音**、**公开涉及他人的内容**，这两件事仍然要在界面上单独确认。

### 3.2 导入

writer 里新增一种文档类型 `oral_history`，目录结构如下：

```
<book>/
  peanut.config                 doc_type: oral_history（构建时仍然按 book 处理）
  oral/
    people.yaml                 人物：讲述者、亲属、反复出现的人名及其写法
    glossary.tsv                专有名词 / 方言 → 规范写法（转写纠错、TTS 读音共用）
    outline.md                  目录规划（3.6 节）
    sessions/
      2026-10-12_01/
        source.m4a              原始录音（只读，永不修改）
        audio.wav               16 kHz 单声道，转写用
        session.json            日期、地点、在场人员、提纲、同意书引用
        transcript.json         机器转写结果 + 人工校对（3.3 节）
        transcript.md           可读版（自动生成）
        notes.md                采访者笔记
    consent/
  chapter1-童年/chapter1_zh.md  成稿，peanutbook 的普通章节
  audio/tracks/...              有声书（现有功能）
```

导入的方式：上传录音文件、手机录音同步到某个文件夹，或者直接在浏览器里录（采访现场用笔记本电脑）。导入时自动做三件事：转码、检查质量、生成波形图。

### 3.3 转写与说话人分离

这是第一个技术重点。

**ASR**：worker 已经有 `asr.py`（目前用 Whisper），再加一种 job：`transcribe`。

- 长音频先用 VAD 切成 20 到 30 秒的片段，再分别转写，输出带时间戳的句子，结果写入 `transcript.json`。
- 进度、取消、断点续跑，直接复用现有 TTS 队列的机制。
- 模型的选择（语言只有普通话和英文两种，所以选择很简单）：
  - **默认用 SenseVoice-Small**（FunASR）：中英文都支持，**中英夹杂**也能处理，自带标点、时间戳和语种识别，速度极快（RTF 约 0.01）。
  - 普通话备选：Paraformer-large，长篇中文的准确率略高。
  - 英文备选：Whisper large-v3（worker 里已经有 Whisper 插件）。
  - 每个 session 自动检测语种，用户也可以手动指定。新增一个 recognizer 插件即可（`RECOGNIZERS`），控制面板上可以选。
- **热词**：把 `people.yaml` 里的人名和 `glossary.tsv` 里的地名、专有名词，作为热词或 initial prompt 喂给 ASR。这一招对人名的提升很明显。
- 速度估算：在 5070 Ti 上，SenseVoice/Paraformer 的 RTF 约 0.01–0.02，Whisper medium 约 0.1。20 小时录音，前者 15–30 分钟，后者约 2 小时。AI 采访模式下每段回答只有几分钟，转写几秒钟就能完成，追问可以马上出来。

**说话人分离**（主路径是一个人讲，AI 采访的问题本来就是文字，所以只有"用户采访家人"这类对谈场景才需要。属于第 2 阶段）：

- 方案 A：FunASR 自带的 CAM++ 说话人模型（CosyVoice 目录里已经有 `campplus.onnx`）做 embedding，再对片段聚类。不需要 HuggingFace token，全部在本地完成。
- 方案 B：pyannote 3.x，效果略好，但需要 HF token 和额外的依赖。
- 先实现 A。用户在界面上把"说话人 1 / 2"改名为"爷爷 / 我"，这个对应关系会记住，后面的场次自动匹配。

**transcript.json 结构**：

```json
{
  "session": "2026-10-12_01",
  "speakers": {"S1": "贺老师", "S2": "采访者"},
  "segments": [
    {"id": "s0042", "start": 754.2, "end": 761.9, "speaker": "S1",
     "asr": "那年冬天雪下得特别大我们走了三天", "text": "那年冬天，雪下得特别大，我们走了三天。",
     "edited": true, "tags": ["童年", "1960s"], "flags": []}
  ]
}
```

`asr` 字段保留机器原文，`text` 字段是校对后的文本。两者都留着，方便以后用更好的模型重跑，而不覆盖人工修改。

### 3.4 校对编辑器（逐字稿 UI）

这是用户花时间最多的地方，必须好用。可以直接复用有声书"Segments 抽屉"的交互：

- 左边播放器加波形图，右边逐句列表。播放时高亮当前句，点哪句跳到哪句（现成功能）。
- 键盘优先：空格播放/暂停，`Ctrl+←/→` 跳到上一句/下一句，回车确认本句并跳到下一句，`Ctrl+R` 重听本句。
- 置信度低的词标黄（Paraformer 和 Whisper 都能给出 token 概率）。
- 说话人可以批量改。支持合并句子、拆分句子（按光标位置和时间戳拆）。
- 选中文字可以打标签：主题、时代、人物、"金句"、"待核实"、"不公开"。
- 全局查找替换，并且可以一键加入 `glossary.tsv`（"以后都把'贺家坪'这样写"）。
- 进度条：本场已校对 63%。

### 3.5 素材库与整理

逐字稿校对完之后，用 LLM 做"读书笔记"（走 `aiassist` 的 provider，本地 Ollama 或云端，可选）：

- **每场摘要**：讲了哪些事，涉及哪些人、哪些年份。
- **事件抽取**：把一件件事整理成 `{事件, 时间, 地点, 人物, 来源片段 id}`，汇总成**时间线**。不同场次讲到的同一件事会自动合并，相互矛盾的地方标出来。
- **人物表**：自动补充 `people.yaml`，比如"二叔：出现在 4 场采访里，3 段经历"。
- **缺口分析**：比如"1978 到 1985 年几乎没有素材"、"母亲只出现在两句话里"，并据此生成**下一次采访的追问清单**。这一点对口述史特别有价值，因为它能直接指导下一次采访。

### 3.6 目录规划

`outline.md` 由编辑决定，AI 只提供 2 到 3 种方案供选择：

- 按时间顺序（最常见）。
- 按主题，比如"山、路、门……"，类似《云层之上》的结构。
- 混合式：时间为主线，章节内部按主题展开。

每一章下面列出要用到的素材片段（拖拽即可把片段放进章节），这一步就是"剪辑"。

### 3.7 AI 辅助成稿（带溯源）

按章节生成初稿，约束要写死在 prompt 里：

1. **只能使用给定的素材片段**，不得添加素材里没有的事实。需要过渡时写成提示，比如 `[此处需补充：当时为何离开]`，不要自己编。
2. **口吻与风格：由用户选择**。可以给整本书设置，也可以给单章覆盖。每章可以同时生成两种风格的版本，并排比较后再选：

   | 风格 | 做法 | 适合 |
   |---|---|---|
   | **原汁原味** | 几乎是原话：只删重复、口误、"嗯啊"，补标点、分段 | 口述实录、家族存档 |
   | **轻度整理**（默认） | 调整语序、合并跳跃的叙述，保留口头禅和说话节奏 | 大多数回忆录 |
   | **文学化** | 散文笔法，加场景描写的节奏，但**事实不得增减** | 出版级自传 |

   另外可以选人称（第一人称"我"，或第三人称传记体），以及中文或英文成稿。中文口述也可以出英文版，交给翻译流程，与 multi-language 打通。
3. **每一段都标注来源**，用 HTML 注释写进章节 Markdown，构建时自动忽略：

   ```markdown
   那年冬天，雪下得特别大，我们走了三天才到县城。
   <!-- src: 2026-10-12_01#s0042-s0047 -->
   ```

4. 生成后自动做一次**核对**：把每句话和它引用的片段再交给 LLM 判断"是否有依据"。没有依据的句子在编辑器里标红，点一下就能听原声。

编辑器里新增"来源"侧栏：光标停在哪一段，就显示对应的原始逐字稿，并可以直接播放那几秒原声。

### 3.8 出书

- **文字版**：就是普通的 peanutbook 书，现有的构建、封面、网站全部可用。可以加一个"原声二维码"：章节里关键段落旁边放二维码，扫码就能听原话。网站版直接嵌入播放器。
- **有声书：两种都支持，用户选择。可以整本统一，也可以按章或按段落设置。**
  - **克隆声音**：用用户自己的口述录音克隆出本人的声音（现有的三步克隆流程，素材直接取自口述中质量最好的片段，自动挑选），用这个声音朗读定稿。效果是"本人朗读自己的书"，而且是润色后的文字。
  - **原声**：直接用原始口述录音。成稿时有 `src` 溯源，所以"原汁原味"风格的章节几乎可以全部用原声拼出来。worker 拼接时截取 `session#start-end`，自动做响度匹配和降噪（复用 `clipcheck` 的降噪链）。
  - **混合**（推荐默认）：引语和关键段落用原声，其余用克隆声音朗读，两者音色一致，听感自然。
  - 实现上，TTS track 的 segment 增加一种类型 `{"source": "2026-10-12_01#754.2-761.9"}`，worker 遇到这种 segment 就截取原音频，不做合成。其余机制（进度、拼接、导出 MP3、逐句高亮、重录）全部复用。

## 4. 隐私与伦理

- **AI 两种都支持，本地优先**：转写、摘要、追问、成稿都**默认走本地**（SenseVoice/Whisper，以及 Ollama 上的本地模型，例如 Qwen 系列，中英文都好）。
  - 本地模型不可用或效果不够时，可以按项目、按任务切换到云端，比如"成稿用云端，追问用本地"。切换时明确提示"内容将发送到 X"。
  - 复用 `aiassist` 现有的 provider 体系（Ollama 加云端），设置放在 `/ai/` 页面。
  - 转写只走本地：录音不出机器。
- 标记为"不公开"的片段永远不会进入成稿 prompt。构建时也做一次检查：如果有引用指向"不公开"的片段，就报错。
- **第三方隐私**：讲述中提到的他人（尤其是负面内容），在审阅阶段要单独列出来，供家属确认。
- 声音克隆必须单独授权。克隆出来的声音只能用在这本书里，删除书的时候提示是否一并删除这个声音。
- **备份**：原始录音是不可再生的。导入后立即计算校验和，并提示备份到第二个位置（NAS 或云盘）。

## 5. 分阶段计划

| 阶段 | 内容 | 依赖 / 复用 | 估计 |
|---|---|---|---|
| **0. 手工流程** | 用现有工具先做一本试点：Whisper 命令行转写 → 手工整理 → 普通 peanutbook 书 | 无 | 立刻可做 |
| **1. 导入 + 转写 + 校对** | `oral_history` 类型、会话导入、worker 的 `transcribe` job（Paraformer/SenseVoice + Whisper，VAD 切片，热词）、逐字稿编辑器 | worker 队列、ASR 插件、Segments 抽屉 | 1–2 周 |
| **2. 说话人 + 标签 + 时间线** | CAM++ 说话人分离、标签、每场摘要、事件和时间线、缺口分析与追问清单 | aiassist provider | 1–2 周 |
| **3. 目录 + AI 成稿 + 溯源** | outline 编辑、拖拽素材、按章生成（带 `src` 注释）、依据核对、来源侧栏 | writer 编辑器 | 2 周 |
| **4. 出版增强** | 原声二维码 / 网站嵌入、原声与克隆混合的有声书、隐私检查 | audiobook、booksite | 1–2 周 |

建议先用一位真实的讲述者走一遍第 0 阶段，录 2 到 3 小时，把真正的痛点（方言？人名？老人讲话跳跃？）找出来，再做第 1 阶段。

## 6. 主要风险

| 风险 | 应对 |
|---|---|
| 方言、口音导致转写准确率低 | 多模型可选，热词，校对 UI 做到最快；必要时人工听写重点段落 |
| 老人叙述跳跃、重复、前后矛盾 | 事件合并和矛盾标记；由编辑决定采信哪个版本，并在 `notes` 里记录理由 |
| AI 润色时"编故事" | 只用引用的素材、`[需补充]` 占位、逐句依据核对、来源侧栏 |
| 录音丢失或损坏 | 校验和、备份提醒、原始文件只读 |
| GPU 资源冲突（转写和 TTS 抢 GPU） | 同一个 worker 队列串行执行，空闲时自动卸载模型（已有） |

## 7. 已确定的决定（2026-10-11）

| 问题 | 决定 | 对设计的影响 |
|---|---|---|
| 讲述者是谁 | **用户本人** | AI 担任采访者（3.1 节）；说话人分离降为第 2 阶段 |
| 语言 | **普通话或英文**（包括夹杂） | 默认 SenseVoice-Small，Paraformer / Whisper 备选（3.3 节） |
| 成稿风格 | **用户自己选**：原汁原味 / 轻度整理 / 文学化，可以按章覆盖 | 三档 prompt，同一章可以生成两种版本对比（3.7 节） |
| AI 在哪运行 | **本地和云端都支持，本地优先** | 复用 `aiassist` provider，按任务切换，转写只在本地（第 4 节） |
| 有声书 | **克隆声音和原声都要，可选，也可以混合** | segment 新增"原声片段"类型（3.8 节） |

### 调整后的第一阶段（MVP）

1. **"讲述"页面**：AI 提问、录音、实时转写、AI 追问（本地 LLM），每一问一答存为 `turn`。
2. **worker 增加 SenseVoice recognizer 和 `transcribe` job**（短录音即时完成，长录音带进度）。
3. **逐字稿校对**：复用 Segments 抽屉，加编辑和标签功能。
4. **"一键成章"**：选几段 turn，选风格，生成一章，带 `src` 溯源。

做完这一阶段，用户就能"讲 → 改 → 成章"跑通一个闭环。素材库、时间线、原声有声书放到后续阶段。
